# 资产与界面约定

用户于 2026-11-14 明确的约定：

1. 新岛屿、新建筑、新道具先用 ImageGen 生成设定图，再参考设定图建模，不先在代码里试拼一个新设计。新增按钮确需新图标时，可用 ImageGen 生成。
2. 既有建筑源于合成材料的拆卸、拼接与组合。迁移须保留材料身份、分块命名、共享主体和附件关系；不能只保留最终外壳便认为完成了合成系统迁移。
3. UI 参考旧 `town-evolution` 当前的 `TownHUD`、`HudLayout`、`ToolTray`、`TrayColumn`、`BottomActions`、`RecipeHandbook`。采用透明左右图标栏、底部浮动入口、按需展开的目录/上下文和右下角手册；先前 WebGL 版的卡片布局不作为本工程 UI 依据。
4. 资源目录不是采用清单。当前旧素材评审明确撤下石块；只保留指定树木 `NormalTree_1:leaves:7` 和 `PineTree_1:leaves:8`。岩石、旧原型树及未确认候选不进入本工程运行清单。

本轮从旧项目复用首批建筑及其升级设计、四类作物与生长阶段、材料数量堆、加工产物、三种物块，以及上述两种指定树。图鉴与游戏场景共用模型来源；工具和库存图标取自旧项目。树叶固定变化已经离线烘焙，原贴图和 CC0 许可保留；没有重新设计树木。

模型由 glTF 离线转换为 OBJ 与色板/原纹理，再交给官方 Content Builder 产生 XNB。旧材质纹理、法线和 UV 均保留。转换时对恒定 UV 增加极小的亚像素差异，避免 Assimp 删除恒定 UV 通道；不改变色板采样。

`assets/selection.json` 是本工程的显式采用清单；`assets/manifest.json` 记录当前源模型散列。原项目保持不变。原始完整 glTF 保留为输入；运行时的合批不意味着可以删除源设计的材料/拆件信息。

当前测试场地沿用本聊天前期已经生成的技术样本，用于镜头、网格、模型和实例缓冲验证，不作为新岛屿内容的美术验收。后续新岛屿重新设计须遵守先设定图再实现的流程。

当前建筑通过静态glTF导入并实例化绘制。`assets/composition.json`保留24个既有设计的分块ID、共享模块、接口与原始脚本散列；运行时的实体合成由规则层消耗明确部件，保留主建筑ID、位置、方向与有效状态，并切换到原项目对应组合模型。尚未实现分块飞行动画、逐件拆解编辑或通用动态组装器。

本轮已接入采集、手动拾取、材料叠堆、32条首批图鉴配方、农作生长和基础加工。各图鉴条目直接从旧项目导出，未发现时隐藏配方。运输、订单、交易、居民和生产自动化仍属后续工作。
