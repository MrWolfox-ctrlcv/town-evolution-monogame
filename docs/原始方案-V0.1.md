# 《小镇进化》新项目方案（讨论版 V0.1）

## 1. 游戏定位

**类型：** 俯视角 / 等距视角的小镇经营、建造与生产自动化游戏。

**核心体验：** 从个人手工业发展为具有农业、加工、物流、贸易和居民生活的自主运转小镇。

**参考方向：**
- 《石炉》：聚落成长、建筑与居民劳动。
- 《王国与城堡》：城市规划、人口需求和外部压力。
- 《异星工厂》：生产链、物流布局与效率优化。
- 《环世界》：借鉴环境压力和系统之间的连锁反应，不以复杂人物故事为核心。

**设计原则：** 玩家首先是小镇的建设者，其次是生产系统的设计者，而不是居民的心理医生或永远替机器搬货的工人。

### 游戏的三个核心支柱

1. **探索与创造：** 材料有实体，建筑通过制作、组合和升级形成，发现新用途本身是一种奖励。
2. **生产与发展：** 种植、加工、储存、物流逐渐从手动劳动发展成自动生产。
3. **适应与经营：** 季节、居民需求、外部订单和环境变化不断改变小镇需要生产什么、储备什么、建设什么。

这三者必须相互影响，而不是三个独立的小游戏系统。

---

## 2. 核心玩法与成长阶段

### 阶段一：荒岛开拓与手工时代

玩家抵达一座资源有限的岛屿，拥有少量工具和基础物资。

最初的玩法集中在：

- 采集木材、石料和农作物。
- 将材料放到地面，用锤子、锯子等工具进行合成。
- 建造第一座房屋、仓库、农田、石窑。
- 通过种植与简单加工获得稳定物资。
- 探索河流、海岸、林地与适合扩建的区域。

**重点：** 保留旧版《小镇进化》最特别的实物合成机制。

建筑不应只是点击菜单扣除资源后凭空出现。材料之间的关系和制作过程仍应有明确的视觉反馈。

不过，进入中期之后必须提供批量建造、重复配方和自动搬运，避免早期的有趣交互变成后期的机械劳动。

### 阶段二：小镇建立与居民劳动

当玩家建成基本住房并提供稳定的食物供应后，开始吸引居民。

居民带来劳动力，也带来消费需求。

最初只需要几个明确的工作类型：农耕、采集、搬运、加工、建造。

玩家可以设定工作优先级、指定工作区域和分配劳动力。

这个阶段不急于引入复杂的人物性格、社交关系和心情系统。

居民首先是小镇经济的一部分：他们生产、消耗、占用住房，同时让城镇呈现生活气息。

**关键设计：居民可以工作，但不应替玩家完成所有策略决策。**

### 阶段三：加工产业与生产网络

随着居民增加，单纯依赖人工搬运与手工加工将逐渐暴露效率瓶颈。

玩家开始建设完整的生产链，例如：

小麦种植 → 收割储存 → 石磨加工 → 面粉运输 → 烘焙坊 → 面包供应。

最初可以依靠居民搬运；随后解锁推车、道路运输、自动装卸和机械输送设施。

生产系统必须支持：

- 建筑明确的输入与输出。
- 仓储和运输容量。
- 生产任务及其原料消耗。
- 供应不足、运输拥堵和产能闲置。
- 自动生产与人工补充并存。
- 玩家对供应优先级的控制。

**重点：物流是需要规划的空间系统，而不是物品在全地图仓库中瞬间传送。**

但底层模拟可以采用批量运输、定时任务和库存变化，不需要为每件物品持续运行物理模拟。

### 阶段四：区域贸易与成熟小镇

当小镇形成稳定产业，目标转向产业规模、生活质量、外部贸易和长期稳定性。

玩家需要决定小镇的发展方向，例如农业贸易、食品加工、林木制造或综合型港口经济。

不同产业争夺土地、劳动力、仓储和运输能力。

成熟的小镇不一定要拥有所有产业。它可以依赖贸易弥补部分资源缺口，但也会承担供应中断和价格变化的风险。

这一阶段应突出“规划一座城镇”的感觉，而不是简单解锁更高级的机器。

## 3. 外部压力：推进游戏，而不是随机惩罚玩家

外部压力是新方案的重要组成部分。

我建议分为三个基础系统，并将战斗与入侵留作未来可选方向。

| 压力来源 | 对小镇的影响 | 玩家可采取的策略 |
|---|---|---|
| 季节与天气 | 农业产量变化、某些运输方式受到影响 | 储备粮食、加工保鲜、发展替代产业 |
| 居民与人口 | 食物、住房、生活用品需求增长 | 扩张农业、提高加工效率、调配劳动力 |
| 区域贸易 | 订单出现期限、价格与需求波动 | 调整生产计划、保留库存、建立更稳定的物流 |

### 外部压力必须遵守的规则

**第一，可预见。** 例如冬季不是突然夺走全部收成，而是提前显示气温变化和农业风险。

**第二，可应对。** 玩家可以通过储备、贸易、调整生产或暂缓人口增长解决问题。

**第三，有连锁反应。** 比如风暴中断港口运输，导致外部物资暂时无法进入，小镇必须依靠现有库存。

**第四，失败可以恢复。** 短期缺粮导致人口增长停滞、生产效率下降，而不是立刻进入不可逆的死亡循环。

### 一个预期中的游戏事件

小镇发展到一定阶段，迎来即将到来的寒季。

居民需要面包，商船提出一份有期限的食品订单，但农田产量即将下降。

玩家可以选择：

- 优先满足居民需求，放弃部分贸易利润。
- 增加粮食储备，推迟其他建设。
- 扩建磨坊和烘焙坊，提高加工速度。
- 通过贸易进口部分原料。
- 投资新的农业技术，为下一季做准备。

这样的压力能自然推动生产网络升级。

**不需要为了制造紧张感，就在小镇旁边刷出一群强盗。**

## 4. 居民系统：保留小镇感，控制模拟成本

我建议初版不要采用《环世界》式完整人物模拟。

居民系统先分成两层：

**经济层：** 人口数量、住房容量、劳动力、岗位、消费需求、工作区域。它决定小镇实际如何运行。

**表现层：** 居民在道路上活动、搬运物品、操作设施、进出建筑，让玩家能够观察小镇的生活状态。

表现层应该反映真实经济事件，但不必让每个居民的逐帧位置都成为生产结算的权威依据。

例如，一次合法的仓库运输任务可以包含货物、数量、起点、终点、运输方式和预计完成时间。表现层再展示相应的居民或推车。

这样既能保留生活气息，也能避免过早陷入复杂的逐个居民寻路与任务调度。

如果后期确定需要个体职业成长、技能或特殊事件，再增加，不作为初版基础。

## 5. 美术方向：模块化方块 3D

**建议采用体素感明显的简化 3D，而不是完整体素世界，也暂不转向纯 2D 像素游戏。**

理由：

- 现有游戏保留真实高差、河岸、桥梁和旋转建造的价值。
- 方块化模型便于统一尺度和组合。
- 建筑升级可以通过添加模型部件直观呈现。
- 农田、机器、道路、箱子、传送设施容易形成统一的视觉语言。
- 可以控制模型复杂度，降低 AI 美术制作和维护的难度。

### 暂定美术约束

- 正交或近正交的固定斜视角。
- 建筑使用模块化体素风格，色板与尺寸标准统一。
- 地形采用高度场与格子占用系统，保留一定的自然高差。
- 人工挖填可以呈现清晰的块状或阶梯形边界。
- 尽量减少复杂 PBR 材质、精细贴图和昂贵的后处理。
- 优先确保建筑的轮廓、输入输出位置与工作状态易于辨认。

**资产制作流程：**

使用 Blockbench 或 MagicaVoxel 制作源模型，统一导出 glTF/GLB。地形、道路连接、运输带和重复结构再通过程序生成。

不再默认由游戏源代码逐个拼接普通建筑的几何形状。

## 6. 技术架构：专用模拟核心，渲染方案待验证

这里暂时不锁定 Godot、Unity、MonoGame 或自研运行时。

先明确游戏真正需要的技术系统。

| 子系统 | 基本要求 |
|---|---|
| 世界 | 网格占用、高程、土地类型、资源与建筑位置 |
| 合成 | 配方、明确的材料来源、制作与组合规则 |
| 生产 | 输入、输出、库存、任务与生产周期 |
| 物流 | 运输节点、路径、容量和货物流动 |
| 人口 | 住房、劳动力、岗位及消费需求 |
| 环境 | 季节、天气、外部订单与事件 |
| 存档 | 版本化游戏数据，不依赖渲染对象 |
| 表现 | 地形、模型、相机、UI、动画和输入 |

模拟应当由独立的数据结构维护，不依靠大量场景节点承担权威状态。

固定步长或事件驱动调度都可以考虑，具体取决于最终的生产与物流规则。

### 技术路线候选

**候选一：C# + MonoGame。**

适合代码优先、固定视角、专用渲染架构。需要自行实现更多场景、UI 和资源管理能力。

**候选二：Godot + 独立游戏模拟模块。**

复用引擎渲染、UI、输入和导出能力，同时避免把每个物品和生产任务都变成场景节点。

**候选三：C++ + SDL3/bgfx。**

针对性最强，但必须承担更多底层开发与平台集成工作。只有前两种路线存在明确无法解决的限制，或者专项验证显示明显收益时，再正式选择。

### 技术选择的依据

三种路线使用同一套小型样本比较：

- 一块有高差的地形。
- 一栋建筑及其升级版本。
- 一块可交互农田。
- 一台具有输入和输出的加工设备。
- 一段可以搬运真实库存的运输系统。
- Windows 与 Android 的真实运行结果。

比较对象不是空场景 FPS，而是开发复杂度、资产导入、交互、帧时、内存、构建稳定性和维护成本。

**不在技术验证阶段开发完整游戏，也不为对比而制造三个长期维护的项目。**

## 7. 实际开发路线

开发采用以可玩结果为标准的阶段门槛，而不是按模块数量或测试数量衡量进度。

### P0：玩法和美术验证

完成一个 20—30 分钟的完整小镇体验。

内容限制为：

- 一张有限的格子地图。
- 木材、石料、两种农作物。
- 手工合成、农田、仓库、石磨、烘焙坊。
- 一条最简单的生产链。
- 一项有明确期限的贸易订单。
- 一个简单的季节变化。
- 保存和恢复。

**验收：** 玩家能明确感受到“手工制作 → 生产设施 → 稳定供应 → 面对外部需求”的成长过程。

### P1：小镇与人口

加入住房、居民、劳动岗位、居民消费，以及基本的工作分配。

**验收：** 增加居民有明确收益，也有可理解的成本；居民劳动能实际减少玩家的重复操作。

### P2：物流自动化

加入推车、道路运输、设施输入输出、运输优先级和自动补货。

**验收：** 玩家可以建设至少一条不依赖手工搬运、连续运行的生产链，并且可以识别和解决其瓶颈。

### P3：外部压力与经济发展

扩展季节、区域贸易、人口需求、库存风险和产业升级。

**验收：** 玩家不仅需要扩大生产，还必须在供给、贸易和居民需求之间做出有意义的选择。

### P4：完整世界与内容扩充

在核心玩法成立后，再扩大地图、加入更多建筑、地形改造、特殊生态、远程贸易与复杂设施。

这一阶段才决定是否需要完整体素地形、地下资源、战斗、防御或更复杂的人物系统。

## 8. 本轮明确不做的内容

为了避免新项目重复旧项目的失控问题，初版排除以下内容：

- 完整人物心理、社交关系和个人故事系统。
- 战斗、袭击、围城与军事科技树。
- 任意方向的三维体素挖掘与洞穴系统。
- 多个地形生成器版本同时长期维护。
- 实时多人、在线经济、云服务。
- 为未来可能存在的功能提前建立通用框架。
- 以大规模自动化测试替代实际可玩性、画面和设备验收。

这些不是永久禁止，而是当前游戏的核心玩法不依赖它们。

## 9. 项目成功的标志

《小镇进化》不是以建造最大的城市、生产最多的物品为唯一目标。

它应该让玩家经历一种清晰的变化：

**最初，玩家为了获得一份面包，需要亲自种麦、收割、磨粉和烘焙。**

**后来，玩家建起农田、磨坊和运输体系，小镇能够稳定生产面包。**

**最终，玩家需要考虑如何让整个小镇在季节变化、人口增长和贸易波动中持续繁荣。**

这个过程就是游戏名称中的“进化”。

技术上的成功标准则是：每增加一项新的资源、建筑、配方或产业，不需要重写整个世界系统，也不需要让 AI 再造一套庞大的基础设施。

**项目应当拥有足够简单的核心，使开发者能够理解它；同时拥有足够丰富的规则，使玩家愿意不断探索它。**
